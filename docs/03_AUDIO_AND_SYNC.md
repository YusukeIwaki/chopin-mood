# 03 — 音響解析と「手調整ゼロ」の同期設計

## 目指している同期は2種類

1. **時間的な同期 (objective)**: 音符・アクセント・セクションのタイミングに映像パラメータやカットが一致する。信号解析と決定的レンダリングでテストできる。
2. **意味的な一致 (subjective)**: 短調の緊迫感、静かな哀愁、解決感などに物語が合う。AIの提案・人間の評価が必要で、現時点で自動品質は未保証。

この2つを混同しない。

## 音声から得る特徴量の候補

| 特徴量 | 用途 | 注意点 |
| --- | --- | --- |
| RMS / LUFS局所推定 | 静→動、照明/カメラの動き | 録音ゲイン・コンプレッサーに影響される |
| Onset strength / novelty | アクセント、音の密度 | レガート・ペダル・アルペジオは難しい |
| Spectral centroid/rolloff | 明るさ・鋭さの補助 | 音域の高さと音色を混同しやすい |
| Chroma / harmonic change | 和声上の変化、セクション境界 | 音が密集すると誤差。感情を直接推定しない |
| Self-similarity / novelty | 繰り返し、構造境界 | 短尺では誤検出しやすい |
| Beat tracking | 拍候補と緩やかな時間感 | ルバートの多いクラシックでは不安定 |
| Optional transcription (piano AMT) | 音域、音符密度、和音の推定 | ペダルや複雑な多声部で誤変換 |
| Optional score alignment | 楽譜位置、繰り返し、フレーズ構造 | 楽譜が必要、実演との対応付けが難しい |
| Optional video motion | 手・腕の大きな動き | 実演らしさの補助、楽音タイミングの主軸にはしない |

## データ処理の基本原理

- 分析で生じる latency は `offset` として記録。中心化STFTや平滑化、映像エンコード遅延等を混同しない。
- フレーズは秒単位、onsetは十〜百ms単位と異なる時間スケールで検出する。
- `energy(t)` をそのまま `zoom(t)` に掛けない。low-pass、移動平均、attack/release、閾値、ヒステリシス、最大変化速度を調整して過敏さを抑える。
- **クラシックに最適化した二段階制御**: 大きな構造（場面・色）をゆっくり、音響イベント（光・粒子）を控えめに短く。
- AIによる物語プランナーには離散的で少数のイベント候補を渡す。高頻度の時間曲線は renderer のみに渡す。
- 解析用に低サンプリングレートへ変換しても、公開用の音声は元動画のトラックまたは高品質マスターを利用する。サンプルレート変換の遅延を管理する。
- 時間の基準は元音声、音源先頭が0秒。クリップ切り出し後は元ソース時間とローカル時間の変換を明示する。
- 映像が派手で音楽のフレーズを壊すなら、反応を抑える方を優先する。

## 3つの自動プランの比較

### A: Naive baseline
RMSを光量・ズームに直接線形マッピング。音に反応する事実の対照群だが、単調・過敏・音楽性の欠如が想定される。

### B: Structured（最優先の検証）
複数の特徴量、局所ピーク、セクション候補を抽出 → Scene planは数カットに制約 → 非カット区間のアニメーションはルールに沿って滑らかに動く。ルバートの変化に追随する、ただしカットの乱発を抑える。

### C: Semantic assisted
Bの構造候補に対し音楽理解モデルが文章で『緊張/緩和/哀愁』等を提案し、story plannerが場面内容を選択。**時刻の採用はBの検出結果・制約で検証**する。モデル間で解釈が揺れる点は評価対象。

## 自動生成で意図的に「人間を外す」箇所

- イベント境界の手修正
- シーンの尺の手調整
- 音楽に合わせた映像速度の手調整
- カットに合わせた音声トリミング（演奏を破壊しない）
- フレーム単位のタイムライン操作

### 人間が選んでもよい低頻度な内容

- チャンネルの世界観（画風、登場人物、作品ごとのテーマ）
- 公開可否の最終判断
- 適切な楽曲/演奏を使うという選曲判断

## PoCで評価する3つの観点

1. **物理的同期**: 同一音声の予定タイムスタンプとエフェクトが指定フレームで対応するか。例: イベント付近±1〜2フレーム。
2. **音楽的自然さ**: 曲想に対し場面転換が不自然でないか、盛り上がりに効果が追従しているか。複数パターンをブラインド比較。
3. **省力化**: 1本の制作に人間が介入した操作回数、介入時間、失敗生成回数、費用を測る。

※±1〜2フレームはタイムライン上の指定位置の検証例であり、音楽的境界検出がその精度で正しいことは意味しない。

## 旧解析の仕様と限界

- 前処理音声: 22,050Hzモノラル → `librosa.load(..., sr=11025)` にてダウンサンプリング。
- hop=256 -> 時刻分解能 約23.22ms。
- RMS（2048フレーム）+ onset（STFTをdB変換）+ spectral centroidを算出。
- RMS（約1.8秒）、onset（約1.3秒）をガウシアン平滑化、10〜95パーセンタイル基準で正規化。
- `activity = smooth(0.7 * normalized_rms + 0.3 * normalized_onset)`。
- 10秒以上離れた局所ピークとして153.0 / 54.0 / 28.2 / 121.6 / 98.9秒など。

旧実装の『音響活動度』は初期プロキシであり、モデルに解釈を与えるための高信頼なフレーズ境界でもタイミングテストの正解データでもない。

## 追加実験

- ルバートが強い音源/アタック明瞭な音源/レガートが多い音源を最低3本で比較。
- BPM追従が破綻する場合、beatを利用せずnovelty / envelope制御でどこまで満足できるか確認。
- 自動音符採譜 vs 音響特徴量のみ vs 楽譜アラインメントのコスト対精度を比較。
- 現場の演奏動画映像は音楽認識への寄与（腕・体の動き）を確認し、意味がなければ切り捨てる。
