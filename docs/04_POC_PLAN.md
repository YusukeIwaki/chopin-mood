# 04 — PoCの工程と受け入れ条件

## P0: 高価なAI生成なしで『音楽と自動同期する』ことを証明する

**最初の出力物**: `output/poc_structured.mp4`, `output/poc_naive.mp4`, `output/analysis.json`, `output/storyboard.json`, `output/qa.json`, `output/cost.json`（費用ゼロまたは実測）。

入力は `assets/reference_audio.wav`（低解像度モノラルの解析素材であり、最終公開用の音源品質はない）。候補が複数ある場合は45秒以内のクリップ区間を解析から選び、選定理由をJSONで残す。今ある5秒集計をそのまま用いるのではなく、少なくとも連続曲線と局所イベントを復元する。

### 作業

1. 依存・ffmpeg利用可否・Remotion等のレンダリング実行可否を調べる。最初は最も簡単なローカルで動く構成にする。
2. 音源を読み、連続したRMS/onset/spectralなどの時系列特徴量、局所イベント候補、フレーズ/セクション候補を生成。
3. 人手編集なしで30〜45秒の切り出し候補と、3〜6シーン程度の自動カット割り案を決定。短すぎるシーンや過密な切り替えを避ける。
4. 画像はサンプル素材や自動生成プレースホルダーで構わない。アニメ調画像の品質ではなく同期を先に評価する。
5. 「構造を尊重して穏やかに反応する」レンダラーと、単純RMS連動レンダラーの両方を作る。
6. FFmpeg/Remotion等で元音源を維持した縦型MP4（1080×1920を目標、PoCは解像度を下げてもよい）を書き出す。
7. QAレポートに元音源長/クリップ開始・終了/ショット数/音声ずれ/黒フレーム検出/音量変化/手操作数/所要時間などを記録する。
8. 自動カット候補と実際のフレーム切り替え位置を可視化して、ユーザーが客観評価できるようにする。

### P0 Done（最初は必須）

- [ ] コマンド1つで入力→解析→映像生成→QAまで動作する。
- [ ] ユーザーが映像と音声のタイムラインを手調整する場面がない。
- [ ] 出力MP4の映像・音声の尺が意図したクリップと一致する（±1映像フレーム程度、コンテナ遅延を考慮）。
- [ ] イベントから決定された映像効果が、スキーマ上指定されたフレームで発火することを自動テストで検証。
- [ ] 30〜45秒の映像内で複数の視覚的変化があり、固定画像を流しただけになっていない。
- [ ] 再実行に必要な seed / versions / input hash / parameters が保存される。
- [ ] 同じ演奏から `naive` と `structured` の出力を比較できる。
- [ ] 現状の弱点がレポートに書かれている（フレーズ分割ミス等を隠さない）。

## P1: 短編物語へ進化

- LLMのシーン解釈を**スキーマ制約あり**で差し込む。
- 元曲の感情を断定せず「この演奏から着想を得た短編」として演出。
- 同じ登場人物・同じ世界観を継続するため `visual_bible` を保持。
- P0のイベントとセクションを保ったまま構図・画風の組み合わせを変更。
- 静止画のAI生成を追加し、同じ尺で自動レンダリング。事前承認と費用上限を設定。

## P2: 重要シーンにだけ動画生成AI

- 4〜8秒カット等を生成し、必要であればタイムストレッチ・トリム・ループ・遷移で自動尺合わせ。
- キャラクター同一性・違和感・制作予算を比較。失敗時は静止画ベースに自動フォールバック。
- 音のアクセントとの緻密な同期は、生成動画内部ではなくオーバーレイ/エフェクト/カット境界で保証。

## P3: 投稿実験（プロダクトマーケット検証）

- A: AIアニメ物語 / B: 抽象映像 / C: 実演とCG融合 を同一演奏で比較。
- 初期には retention, average view duration, registered viewers conversion, long-form migration などを比較。
- 動画数だけでなく手作業時間 / 投稿1本コスト / 内容重複感を評価。

## 推奨テスト（自動化）

- クリップ区間・イベント秒→フレーム対応の境界値テスト。
- 無音・小音量・急アクセント・高音域だけの変化・クロップ位置のパターンテスト。
- 同じ入力・同じseedで同じ制御タイムライン/動画構造になること。
- シーン境界はソート・最小尺・隙間なし・重複なしであること。
- 映像/音声の最終継続時間をffprobeで検証。
- 音声の変化はAACなどの再圧縮を許容し、**サンプル完全一致と取り違えない**。必要に応じてデコード後の相関・ずれ・音量差を測る。

## Codexに提案してほしい意思決定

- 最初のローカルレンダラーに Remotion / ffmpeg filtergraph / Python / Blenderのどれが最短か。
- 最小のイベント抽出で十分か、フレーズ分割に別手法が必要か。
- 音色変化が「音域だけの変化」と取り違えられる問題の現実的な対処。
- 制作時間と品質のトレードオフを測る実験方法。
