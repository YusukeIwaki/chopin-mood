# 録音レートに対する解析窓の校正

2026-10-21。文書09に残していた録音レート依存の誤差を検証した。
親が独立測定と変更条件を決め、Muse
`muse-wonder-1.0-contributor / max / --yolo` が解析と呼び出し側を変更した。
途中でMuseの利用上限に達したため、親がメタデータを整理し、テスト・
再測定スクリプト・実音源の検証を仕上げた。音声の外部送信はない。

## 変更と採用理由

従来の既定値は全録音レートで hop=512、FFT長=2048サンプルだった。
48kHzでは22.05kHzの半分以下の時間幅になり、周波数分解能も変わる。
今回、音源のネイティブレートで約23.22msのhop、約92.88msの窓に揃えた。

| 録音レート | hop | FFT長 |
|---|---:|---:|
| 22,050Hz | 512 | 2048 |
| 44,100Hz | 1024 | 4096 |
| 48,000Hz | 1115 | 4458 |

式は `hop=max(1,round(512*sr/22050))`、
`n_fft=max(2,2*round(1024*sr/22050))`。窓は偶数に丸める。
音源・解析信号をリサンプルせず、時刻は引き続き元の整数サンプル位置。
開発時の明示的なhop/FFT長指定は維持する。実際の設定、時間幅、基準レート、
指定の有無を記録し、plan内の古い固定値も実際の値に置き換えた。

48kHzの時間格子は従来の約10.67msから約23.23msになる。
時間と周波数の分解能の交換であり、すべての音響検出を高精度化する変更ではない。
アタックの校正は別に行い、今回の単一impulseでは各レート・2ゲインで
誤差が1hop以内に収まることを確認した。

## 合成信号によるA/B結果

同じ連続時間の正弦波和音と等電力クロスフェードを各レートで生成した。
比較対象は同じコードに旧設定を明示したもの。既知の変化中心との誤差は
音響的校正であり、フレーズ終止の正解率ではない。

| 校正条件 | 旧設定の最大誤差 | 時間幅を揃えた設定 |
|---|---:|---:|
| 22.05kHz、2中心/lag条件×2ゲイン | 31.89ms | 31.89ms |
| 44.1kHz、同条件 | 101.63ms | 31.89ms |
| 48kHz、同条件 | 149.00ms | 14.65ms |
| 別の和音、5レート、2変化速度の10条件 | 67.00ms | 22.25ms |

初期12条件と追加10条件は、旧設定・新設定とも比較区間内の検出欠落0、
候補の重複0。最寄りピークの誤差だけでなく、検出件数も記録する。
追加条件は実装を採用する前に指定したが、合成信号であり未見の演奏ではない。

**残存する問題:** 音高クラスが変わらないオクターブ移動でも、
新旧とも10条件すべてでharmonic novelty候補が出る。
「和声変化の認識に成功した」と扱わない。正規化された強さを信頼確率と
呼ばず、音域変化・微小なchroma変化を抑える方法は別の比較実験とする。
今回、都合のよい絶対しきい値を足してこの問題を隠す変更はしていない。

## 実音源と機械QA

- `assets/reference_audio.wav`（22.05kHz）では、新旧のイベント全件と
  Studio抜粋候補・シーンが完全一致した。既定値と旧明示設定の
  特徴量配列も回帰テストで完全一致を確認した。
- Issue #1のローカル復号素材（48kHz）は約63.77秒から64.4秒の候補へ変化。
  元サンプル区間は `[6816000, 9907200)`、30fpsで1932フレーム。
  共通設定の変更による自動再選択で、秒指定・カットの手修正は0件。
- 同素材のアタック候補は156→192件、構造候補は30件のまま。
  候補数の増加を音楽的な改善とは判断しない。演出の間引き条件は維持した。
- 2音源ともSHA256は変化なし。既存の検証成果物を上書きせず、
  新しい成果物は `output/independent/issue1-tuned/bundle/` に保存する。
- 全154テストが成功。新しい実音源MP4（540×960、64.4秒）も11項目の
  機械QAが成功した。音声の全体・前半・中盤・後半でずれ0サンプル、
  区間間ドリフト0、音量差−0.008dB、cropは元区間と完全一致。
  planの解析設定は実際の1115/4458と一致し、bundleのハッシュも再照合した。

映像は既存の手続き描画を使った検証用フォールバック。完成アニメでも、
「疲れ・回想」という創作意図への美的承認でもない。端点の聴感上の自然さ、
ルバート・ペダル・多声部への精度、未知の演奏3本以上での無調整運用は未検証。

## 再現

```bash
.venv/bin/python scripts/calibrate_sample_rate.py
.venv/bin/python -m pytest tests/test_sample_rate_features.py -q
.venv/bin/python -m pytest tests -q
```

`output/calibration-sample-rate.json` に全64件（32条件×新旧）の設定・検出位置・
誤差・検出件数・処理時間・コードハッシュ・依存バージョンを保存する。
このスクリプトの終了コード0は報告書の生成成功を表し、音楽品質の合格ではない。

次の検証は、別の開発素材を用いた弱いchroma変化の棄却比較と、
保留した演奏素材での音楽的自然さの評価。今回の2音源を未見評価用とは数えない。
